# Checklist Engine 0.3.0

[English](README.md)

Движок собирает доверенные Python-классы в зашифрованные бандлы и
исполняет именные и встроенные чек-листы. Версия пакета — 0.3.0.
Формат бандла — 2. Номер выпуска внутри бандла — отдельное целое число.

## Автономная демонстрация

Используйте Python 3.12 или новее и укажите новый выходной каталог.

~~~console
python -m pip install --only-binary=:all: -r requirements.txt
PYTHONPATH=src python examples/example.py --output demo-run
~~~

В PowerShell используйте настройку окружения и команду ниже.

~~~powershell
$env:PYTHONPATH = "src"
python examples/example.py --output demo-run
~~~

Демо проверяет сборку, запуск, повторы, таймаут и компенсацию.
В новом каталоге создаются два отдельных бандла и база состояния
SQLite. Транспорт и сеансовые ключи симулируются.

## Сборка и приёмка выпуска

Определите класс в Python-файле и унаследуйте его от Step или Checklist.
Передайте в build_bundle все классы, на которые ссылаются планы.
Сборщик проверяет структуру извлечённого класса и ссылки на шаги до
публикации. Импорты, нужные методам, размещайте внутри методов.
При загрузке доступны публичные классы контрактов, встроенные имена
и стандартные модули из vault.py. Учитывайте эту среду для тела класса
и аннотаций. Сборщик сохраняет режим отложенных аннотаций, если он
задан импортом из __future__ в модуле автора.

~~~python
from engine import ChecklistRunner
from vault import SQLiteReleaseState, load_release_bundle

state = SQLiteReleaseState("private/accepted.sqlite3", "dispatch")
registry = load_release_bundle("bundles/current.py", key, state=state)
report = ChecklistRunner(registry).run("secure_dispatch")
~~~

При первичной установке явно задайте allow_initial=True. Для обычной
загрузки оставьте значение по умолчанию. Транзакция отклонит выпуск
с меньшим номером или иной бандл с уже принятым номером. Для допустимого
выпуска она загрузит каждый класс и проверит имена, политики, планы и
указанные в них шаги до фиксации версии. Для этих шагов проверяются
синхронность и возможность вызвать доступный для анализа конструктор
без аргументов. Прямое создание экземпляра поддерживает аргументы.
Тела классов исполняются с правами процесса внутри транзакции записи,
включая повторную загрузку принятого дайджеста. SQLite может откатить
запись о выпуске. Приложение управляет внешними эффектами доверенных
классов. Другие хранилища реализуют accept(release, *, prepare),
проверяют допустимость выпуска до однократного вызова prepare и
фиксируют версию после его успеха.
Храните базу состояния и каталог бандлов под контролем приложения. Оно
хранит принятый файл и определяет, когда активировать реестр.

Строгий файловый вход принимает str и PathLike[str]. Он читает
литеральные данные и проверяет манифест до выдачи реестра. BundleLimits
задаёт предельные размеры. Значения по умолчанию — 1 МиБ на файл,
4096 записей, 256 байт UTF-8 на имя и 256 КиБ закодированных данных
на запись. Совместимый load_bundle сохраняет min_version и приём
доверенных словарей и модулей. Для поставляемых файлов используйте
load_release_bundle.

build_bundle эксклюзивно создаёт временный файл в каталоге назначения,
синхронизирует его, заменяет целевой файл и на POSIX синхронизирует
каталог. Параллельные сборщики публикуют целые файлы в порядке
фактической замены. Допуск версии проверяет состояние выпуска.

## Исполнение

Перед первым действием движок проверяет весь план. Запись содержит
имя, одноэлементную последовательность или пару имени и параметров.
Параметры становятся именованными аргументами run. Context общий
для одного прогона.

- ABORT останавливает выполнение. CONTINUE продолжает. ROLLBACK
  вызывает доступные компенсации завершённых шагов в обратном порядке.
- Указывайте retry_safe=True для шагов, которые безопасно повторять.
  Режим совместимости для доверенных вызовов — allow_unsafe_retries=True.
- step_timeout относится к одной попытке run. step_total_timeout
  охватывает загрузку, конструктор, попытки и паузы одного шага.
  undo_timeout задаёт предел каждой компенсации. Движок копирует
  настройки политики в начале прогона.
- Context.time_left() возвращает остаток времени по монотонным часам.
  Движок может использовать свободный Unix-таймер в главном потоке.
  SecureRegistry откладывает прерывание движка на время поиска класса.
  Ожидающий вызов ограничен остатком бюджета. Вызов, который загружает
  класс, проверяет срок до и после поиска. Дедлайн Context охватывает
  и поиск чек-листа по имени. В остальных случаях без
  Unix-таймера шаг сам соблюдает дедлайн. Просроченный результат
  считается ошибкой, включая обработанный StepTimeout. Жёсткое
  ограничение произвольного блокирующего вызова требует надзора
  за отдельным процессом.
- Отчёт фиксирует итог шага и число фактических вызовов. Компенсация
  имеет отдельную фазу и может завершиться ошибкой или быть пропущена.
  Диагностические коды позволяют ограничить вывод исключений контракта.

## Криптография

AES-GCM-SIV защищает исходники контрактов со случайным 12-байтовым
nonce. Имя записи входит в аутентифицируемые данные. Манифест формата 2
связывает формат, шифр, время создания, номер выпуска и дайджесты
шифротекстов с именами записей. Имена сортируются при расчёте
манифеста. Бэкенд должен поддерживать пустое AEAD-сообщение.

Для ключа бандла из парольной фразы используйте derive_bundle_key.
Общий derive_key поддерживает допустимые длины HKDF. Argon2id по
умолчанию использует 3 прохода, 4 линии и 64 МиБ. HKDF-SHA3-512
привязывает ключ к назначению. Сохраните уникальную соль и параметры
KDF в конфигурации выпуска. Проверяйте штатные операции шифрования,
манифеста и KDF на целевой платформе с закреплённым колесом PyCA.
